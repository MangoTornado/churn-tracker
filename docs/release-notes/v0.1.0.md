### First release

A churning tracker that answers with dates. Every rule in this space is a time window — 5/24, 2/90,
1/8, 6/24 — so nothing here tells you "no". It tells you *until when*.

**Your position, as the rule's own shape.** The 5/24 count is drawn as five slots, each spent one
labelled with the month it frees up. One glance gives you both how many you have and when the next
one comes back, which a number on its own cannot.

**Twenty-five issuer rules, each returning a date.** Chase's 5/24 and its three-month velocity
guidance, Amex's 2/90, one-in-five-days, five-credit-card limit, card-family rules and lifetime
language, Citi's 1/8 and 2/65, Barclays' 6/24, Bank of America's 2/3/4 and 3/12-or-7/12, Capital
One's opaque underwriting, plus per-card and shared-family bonus cooldowns. Ask about any of 107
catalogued cards and you get every rule that bears on it, named in the notation you will find it
under elsewhere, and the date each one lifts.

**Reminders for the deadlines that cost money.** Annual fees six weeks out, the ~30-day window to
reverse one that has already posted, minimum-spend deadlines with the shortfall named, bonuses that
met their terms and never arrived, bank bonuses that have become safe to close, and idle no-fee cards
about to be auto-closed for inactivity. Ordered by date, then by how much is at stake.

**What to apply for next**, following /u/m16p's Card Recommendation Flowchart (v21, updated
2025-06-09) — quoted and attributed rather than paraphrased. Under 5/24 the plan is Chase-first with
business cards as spacers, because Chase cards are the only ones the count can take away from you;
past it, the biggest bonus a bank will still approve. Cards the chart groups on one line are shown as
one recommendation with alternatives, because "United Quest, Explorer and/or Club" means pick one.

**Live bonus data** from Doctor of Credit: 70 card offers and 250 bank offers, refreshed daily and
checked into the repo as a snapshot so the app still works with the network down.

**Two-player mode**, because a couple churning together runs two separate 5/24 counts and two
separate Amex histories while sharing one login.

### What it will not do

It never asks for a bank credential and cannot connect to an account. There is no aggregator, no
Plaid key, no account number, no balance, no transaction feed. Dates and dollar amounts you type in
are all the rules need — which is the point, not a limitation: a tracker that cannot move money is a
tracker whose breach is a nuisance.

### Known gaps

- **iOS is not in this release.** A distributable iOS build needs an Apple Developer account and
  provisioning profiles that cannot live in a public repo. The project builds and runs on iOS from a
  Mac — see [RELEASING.md](docs/RELEASING.md) — it is just not shipped here.
- **Push notifications need an EAS project id** to mint tokens in a standalone build. Without one the
  Settings screen says so and everything else works.
- **The bonus parsers are heuristic.** Doctor of Credit publishes prose, not tables, so about a third
  of card offers do not match a catalogued card. Those are still listed, just without rule checking.
- **No iOS/Android sync conflict UI.** Sync is last-write-wins per row; a rejected upload is reported
  to the client but there is no screen to reconcile it by hand.

### Accuracy

These rules are community-observed issuer behaviour, **not issuer policy**. Almost none of it is
documented, all of it changes without notice, and the flowchart's own limitations panel leads with
that. So the app always names the rule it is applying, always says when it expects the answer to
change, and never stops you recording something it thinks is impossible. You are the one who gets
denied.

### Under the hood

The server has **zero npm dependencies** — Node 24 runs its TypeScript directly and `node:sqlite` is
built in, so there is no build step and no lockfile. 251 tests, run in three timezones because every
date bug here has been a UTC-versus-local off-by-one that passes under `TZ=UTC`.

One container serves both halves: the web app at `/` and the API under `/v1`, so opening the hostname
is the entire setup — the app takes the origin it was served from as its API. 248MB, arm64, deployed
with Kamal 2.
